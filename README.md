# 低估价值挖掘系统

**机械层收集信息，模型层做判断。** 用代码把全市场信息尽可能收全并精算，
交给模型用资深价值投资的思维推理出值得投资的标的。

方法论定义见 [`SYSTEM_DEFINITION.md`](SYSTEM_DEFINITION.md)。零依赖，只用 Node 内置模块。

## 用法

```bash
node mine.js mine cn          # A股全市场挖掘（四阶段，十几分钟）
node mine.js mine us          # 美股全市场挖掘
node mine.js mine cn --no-llm # 只跑机械层，不调模型

node mine.js watch mine us    # 自选池挖掘（三阶段，不粗筛，1 次模型调用）
node mine.js watch mine cn

node mine.js analyze 600519   # 单股低估判定
node mine.js analyze 联合健康  # 支持中文名

node mine.js watch add 600519   # 加入自选池（代码或名称）
node mine.js watch remove 600519
node mine.js watch list         # 查看自选池

npm start / stop / status / logs   # Web 服务，默认 http://localhost:8788
```

模型凭据缺失时会打印可直接粘贴的 export 引导（自动探测 `MODELBEST_API_KEY`）。

## 两条流水线，分开点击

**市场挖掘**找的是你还不认识的标的；**自选池挖掘**回答你盯着的这些现在该不该买。
两件事问题不同，所以各跑各的、各出各的榜，互不占用名额。

```
市场挖掘（四阶段）            自选池挖掘（三阶段）
阶段1 全市场信息收集           阶段1 只收池内这几只（A股走逐股财务指标）
阶段2 模型粗筛 6/5 批 名额 50   ——  不粗筛：点名的票不必跟全市场抢入场券
阶段3 深度补数（≈50 只）        阶段2 深度补数（池内全员）
阶段4 总裁决 → 纯市场 Top 10    阶段3 自选池裁决 → 值得买 ≤8 + 其余逐只落选理由
模型调用 A股 7 次 / 美股 6 次    模型调用 1 次（>15 只时分批：批数 + 1）
```

池子超过 15 只自动分批：批内先初筛（按行业聚拢、并行），终裁只看入围的十来只。
原因是输出侧的硬限制——让模型一次写出 43 份结论，它会思考十几分钟然后一个字都不写
（实测 `stop_reason=end_turn`、正文 0 字）。分批后每次调用的输出量恒定。

网页四个按钮：顶栏「挖掘 A股市场 / 美股市场」，自选池面板内「挖掘 A股自选 / 美股自选」。

阶段 1 零逐股请求——实测 A股 23 次 / 美股 119 次 HTTP 覆盖全市场
（人均 0.005 / 0.08 次）。逐股请求只在深度补数阶段发生。

## 自选池

手动维护的长期跟踪名单（网页「＋自选」或 CLI `watch add`，存 `watchlist.json`，
**纯手动进出**：不自动入池、不自动出池）。

自选池挖掘的一条铁律：**池内每一只票都必须有结论**。没进「值得买」的，逐只给三句话
（现在什么状态／为什么现在不该买／什么条件下重新考虑）加关键数据，网页折叠、点开可看；
模型漏答的显式标「未给结论」，绝不静默消失。判为陷阱的提示「建议移出」，但不自动删——
池子是你的意图，系统只能建议。

一只都不值得买时就如实说，不为凑满 8 只而放水。池内票落在挖掘池排除项内
（ST／流动性不足／美股金融地产）照常分析，只标注估值口径适配有限。

## 为什么机械层不做判断

早期版本是「四层机械漏斗 + 末端模型」，实测发现机械层替模型做了最关键的商业判断：

```
UNH   归一化 EPS $32.61        实际 EPS $13.23
```

系统假设医疗成本率会回到 7 年中位数，据此算出 55% 安全边际并放行。
但「利润率会不会回来」恰恰就是"一次性冲击 vs 结构性衰退"的判断——这该由模型做。

同样，F-Score 衡量的是**财务改善程度**，而一次性冲击中的好公司必然 ROA 下滑、
现金流转弱，正是最该找的那一类会被硬门槛砍掉（实测 A 股淘汰的 949 只里 481 只死于 F-Score）。

现在这些指标照算，但只作为给模型的信息。

## 数据源

| 用途 | 来源 |
|---|---|
| 全市场列表 / 行业 / 市值 / 跌幅 | 东财 clist（美股 `f100` 即 GICS 一级行业） |
| 52 周高低 | 腾讯批量行情，200 只/请求 |
| A股财务指标 | 东财 `RPT_F10_FINANCE_MAINFINADATA`：全市场挖掘按报告期整市场查，自选池挖掘逐股查 |
| 美股财务指标 | **SEC frames**，一次调用返回某概念某年的全市场值 |
| A股估值分位序列 | 东财 `RPT_VALUEANALYSIS_DET` |
| 美股估值分位 | 腾讯月线 × 报表反算（PIT 口径） |
| 新闻与公告 | 东财资讯搜索 + 个股公告 |

## 踩过的坑

- 东财 clist 的 `f2`（最新价）在美股缩放不一致（NVDA ÷1000、BRK.A ÷100），**不可用**。
- `LOAN_PROVISION_RATIO` 是拨贷比（2.8%），拨备覆盖率是 `BLDKBBL`（217%）。
- SEC frames 的资产负债表科目要用 `CY2025Q4I`（时点），利润表现金流用 `CY2025`（区间），
  混用会全部取空。
- SEC frames 必须**跨标签合并**：`Revenues` 对多数公司有值就会被当成命中，
  实际用 `RevenueFromContractWithCustomer...` 的公司（如 AAPL）永远取不到。
- 新闻检索**必须用中文名**：`UNH` 仅 3 条噪音，`联合健康` 195 条。
  另需过滤 ETF 持仓播报与同名机构（「复星联合健康」），实测滤除率 90%+。
- `glm-5.3-flash` 的 reasoning 计入 `max_tokens`。77k token 的输入需要 64000 预算，
  给少了会被思考吃光、正文为空。
- **模型协议由网关的渠道声明决定，不由供应商品牌决定**。换渠道前先查 `/v1/models`：
  `ANTHROPIC` 走 `/v1/messages`，`OPENAI_HTTP` 走 `/v1/chat/completions`。
  用错端点会被回 `400 该模型未声明支持 Anthropic Messages 协议调用`——而这错误**只经 SSE 回前端、
  不写日志**，界面上就表现为「没有触发模型调用」。
  换模型改 `src/config.js` 的 `NARRATIVE.model`，或用 `MINE_MODEL` / `MINE_FALLBACK_MODELS`
  覆盖；协议自动探测，必要时 `MINE_PROTOCOL=anthropic|openai` 钉死。
- 网关把错误也包成 `HTTP 200 + SSE error` 返回（「模型不存在」实测如此），
  所以判「这条协议能不能用」必须读到**第一个有效事件**，不能只看状态码。
- **「渠道支持某协议」≠「渠道支持该协议下的工具调用」**。协议探测只发 1 token、
  不带 `tools`，答不了后者。工具能力用 `node .run/probe-tools.mjs` 单独验。
  实测 `GPT_bhlzrh` 在 OpenAI 协议下工具往返完整可用；Anthropic 协议它压根不声明。
- **带 `tools` 的首轮是「正文 0 字 + `stop=tool_calls`」，这是正常形态不是故障**。
  旧的「空正文一律失败」判据会把它当故障，还会烧掉整条降级链——
  所以工具循环走 `completeWithTools()`，不走 `complete()`。
- **A股公告正文免费且不用解析 PDF**：`np-anotice` 的 `art_code` 喂给
  `np-cnotice-stock.eastmoney.com/api/content/ann`，`notice_content` 就是纯文本。
  注意响应里的 `page_size` 是**总页数**不是每页条数（茅台半年报 44 页 × 5000 字）。
- **财报分节抽取的三个坑**（`src/sources/filings.js`）：
  ① 目录簇窗口不能太宽——AAPL 正文里 Item 4「Not applicable」、Item 6「[Reserved]」极短，
  取 3000 字符会把正文判成目录；真目录密度高一个量级（6 条 341 字符）。
  ② 交叉引用**会把完整章节名写全**（`Item 7 <完整标题> of this Form 10-K`），
  所以判据要紧贴标题末尾，章节名正则必须吃掉完整标题而非前缀。
  ③ 行内标签要删成**空串**不是空格：`<span>R</span>isk` 换成空格会变成 `R isk`，
  整节抽取直接失败。
- **后复权价不能直接展示给模型**。它只适合算比值：茅台后复权 2021-10 是 9661.08，
  模型会读成「当时股价 9661 元」（实际约 1800）。要按现价重新锚定。
- 东财 `push2`/`push2his` 域名常被重置，仅 `82.push2` 与 `push2delay` 稳定。
  v0.7.0 起回撤重新用到 `push2his`（月线 `klt=103`），但做了三级兜底，不硬依赖它。
- **回撤和估值不能共用一条价格序列**。反算市值要不复权（复权价 × 股数 ≠ 当时市值），
  算收益率必须复权。共用的代价实测过：NVDA 三年收益写成 −47%（真实 +364%，10:1 拆股）、
  KLAC 52周收益 −84%（真实 +109%，6:1 拆股）、茅台五年 −32%（真实 −5%，差额全是分红）。
- **复权要用后复权 `fqt=2`，不要用前复权 `fqt=1`**。前复权从最新价往前扣现金分红，
  长窗口叠加拆股会扣穿零：实测 NVDA 日K 222 个非正收盘、茅台 369 个、KLAC 9 个。
  回撤只取比值，后复权不影响结果且数值稳定。
- **腾讯 `fqkline` 的复权参数只对 A股 生效**。A股 传 `qfq` 后响应键会变成 `qfqmonth`
  且数值确实变了；美股三种取值返回分毫不差、键仍是 `month`。所以必须校验键名——
  拿到不复权数据却以为已复权，是最难发现的一类错误。
